## 1. 한 줄 컨셉

> 매일 새벽에 등록한 사이트들을 훑어 "국내보다 충분히 싸게 들여올 수 있는 상품"을 찾아 아침 텔레그램으로 10건만 보여주고, 내가 승인한 것만 한국어 상세페이지까지 만들어 등록 직전 상태로 넘겨준다.

사람이 하는 일은 세 번의 클릭이다. 1차 승인(조사할 가치가 있는가), 2차 승인(이대로 올려도 되는가), 그리고 엑셀을 스마트스토어에 올리는 것.

## 2. 왜 이렇게 설계했나 (핵심 원칙)

- **사이트 차이는 어댑터가 흡수한다.** 1688 전용이 아니라, 소스(사이트)를 관리자가 등록하고 어댑터 3종(내장 / 범용 CSS 셀렉터 / LLM 추출) 중 하나로 붙인다. 파이프라인 ③ 이후는 소스가 무엇이든 동일하다.
- **표기 차이는 사전이 흡수한다.** 과자 = 스넥 = 零食 = お菓子 = snack 처럼 사이트마다 다른 분류·속성 표기를 표준 카테고리와 별칭 사전으로 하나로 모은다. 모르는 표기는 LLM이 제안하고 관리자가 확정하면 사전에 쌓인다.
- **비용은 전부 넣고, 값은 관리자가 바꾼다.** 소스가, 현지 배송비, 배대지(경로별 배송 프로필), 관부가세(목록통관 150달러 경계), 네이버·결제 수수료까지 넣어 마진율을 계산한다. 기본값은 평균치이고 전부 관리자 설정이다.
- **사람이 거른다는 전제로 자동화한다.** 매칭 오판은 피할 수 없으니 정확도 프리셋으로 조절하고, 카드에 근거를 보여주고, 2단계 승인으로 막는다.
- **돈이 드는 단계는 승인 뒤로 미룬다.** 상세 수집과 콘텐츠 생성은 1차 승인된 상품만 실행한다. 월 API 예산을 두고 80%에 경고, 100%에 중단한다.
- **단순한 인프라.** 집 PC 한 대, SQLite 상태 머신, 단일 워커, FastAPI 관리자 웹. 큐나 브로커 없음.

## 3. 전체 흐름 (요약)

```
새벽(설정 시각)  ① 소스별 수집 → ② 정규화·필터 → ③ 네이버 매칭 → ④ 원가·마진율 계산
아침(설정 시각)  ⑤ 텔레그램 1차 카드 (마진율순 상위 N건, 기본 10)  [승인][거절][보류]
승인 즉시        ⑥ 상세 수집 → ⑦ 콘텐츠 생성(한국어화 · 상세페이지 이미지) → ⑧ 텔레그램 2차 카드  [패키지 생성][수정 요청][폐기]
승인 즉시        ⑨ 이미지 Supabase 업로드 → 네이버 일괄등록 엑셀 행 생성
등록 후          ⑩ 설정 주기로 소스 재점검 (품절 · 가격 · 옵션 · 최소수량 · 삭제) → 텔레그램 [판매가 수정][판매 중지][무시]
```

## 4. 기능 목록

### 수집 · 정규화
- 소스 관리: 사이트 등록, 국가·통화, 어댑터 종류, 로그인 프로필(브라우저로 1회 수동 로그인), 요청 지연·하루 상한·차단 허용, 배송 프로필, 헬스
- 어댑터: 내장(1688·타오바오·알리·NETSEA·슈퍼딜리버리 코드 작성), 범용 CSS(관리자가 셀렉터 입력 + 1페이지 테스트), LLM 추출(셀렉터 없이 시작, 나중에 셀렉터 제안받아 승격)
- 수집 카테고리: 소스별 목록 URL과 표준 카테고리 매핑
- 카테고리 매핑: 표준 카테고리 트리(네이버 코드·품목 유형·기본 무게), 언어별 별칭 사전, 속성 별칭(재질), LLM 제안 확인 대기 큐
- 정규화: 통화 환산, 언어 감지 → 한국어 검색어, 재질·품목 코드화, 카테고리 표준화, 브랜드 로고 감지(비전 LLM) → 자동 제외
- 제외 규칙: 재질 / 품목 유형 / 키워드 / 브랜드 로고. 코드 기준이라 언어·사이트가 늘어도 규칙은 하나. 식품 등 목록통관 배제 품목은 기본 제외

### 비교 · 원가
- 네이버 쇼핑 검색 API(공식)로 상위 N개 수집, CLIP 이미지 유사도 + LLM 판정으로 정확/유사 매칭 분류
- 소스 간 동일 상품 그룹핑 → 최저 원가 소스 표시
- 환율 자동 수집(수출입은행 API → 네이버 금융 크롤링 → 마지막값), 수동 입력 없음
- 배송 프로필(경로별 요율표·현지 배송비·배송일), 관부가세, 수수료, 목표 마진율
- 무게 미확인은 0으로 두되 경고 플래그

### 승인 · 생성 · 산출
- 텔레그램 1차/2차 카드, 수정 요청 메모 → 재생성, 보류 → 다음날 재알림
- 콘텐츠 생성 모드 A(외국어 제거) / B(한국어 삽입) / C(상품 사진 소재로 템플릿 재구성). 상품 실물 사진은 생성하지 않음
- 구매대행 고지 블록(국가·배송일 변수), 금지 문구 검사
- Supabase Storage 업로드 → 공개 URL → 네이버 일괄등록 엑셀. 판매가 = 총원가 ÷ (1 − 목표 마진율), 100원 올림

### 등록 후
- 관리자가 "등록 완료"(스토어 상품번호·판매가) 표시 → 감시 대상
- 설정 주기(기본 3일)로 소스 재점검, 가격 변동 임계값(기본 ±5%), 품절·옵션 품절·최소수량·삭제·복구 감지
- 결정: 판매가 수정(엑셀 수정 행) / 판매 중지 / 무시

### 시스템
- AI 제공자 선택: 텍스트 LLM(Claude / Gemini / OpenAI), 이미지 생성(Gemini / OpenAI). 모델·API 키·연결 테스트. 키는 .env 또는 화면(암호화), 화면 값 우선
- API 월 예산, 경고 비율, 초과 시 동작
- 배치 스케줄(수집 시각·알림 시각·요일), 배치 미실행 경고
- 관리자 웹 메뉴 11개: 대시보드, 소스 관리, 카테고리 매핑, 수집 카테고리, 제외 규칙, 비용 설정, 매칭 설정, 콘텐츠 설정, 상품 목록, 실행 로그, 시스템 설정

## 8. 구현 순서 (제안)

1. 뼈대: 프로젝트 구조, DB 모델과 시드, 관리자 로그인·소스 관리·카테고리 매핑·시스템 설정 화면
2. 첫 소스: 1688 내장 어댑터 + 정규화기, 카테고리 1개로 끝까지 데이터 확인
3. 비교: 네이버 매칭기 + 원가 계산기(배송 프로필, 환율 어댑터)
4. 알림: 텔레그램 1차 카드와 승인 콜백, 스케줄러
5. 둘째 소스: 범용 CSS 어댑터로 일본 사이트 1곳, 소스 간 그룹핑
6. 상세·산출: 상세 수집, 콘텐츠 모드 A, 2차 카드, Supabase 업로드, 엑셀
7. 등록 후 감시(⑩), 예산 집계
8. 확장: LLM 추출 어댑터, 모드 B/C, 추가 내장 어댑터, 쿠팡

## 8-1. 지금 돌아가는 것: URL 즉시 분석 CLI (2026-10-30)

구현 2단계의 첫 조각. 윈도우·맥별 설치와 테스트 순서는 [SETUP.md](SETUP.md). 상품 URL 하나를 넣으면 페이지를 읽고(Playwright), LLM이 정보를 뽑아 한국어로 정규화·요건·브랜드 판정을 하고, 네이버 통합검색 크롤링으로 비교가를 찾아 원가·마진율·후보 점수를 계산해 카드로 출력한다. 결과는 `data/analyses/` 에 이력으로 남는다.

```bash
# 1) 준비 (최초 1회)
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
copy .env.example .env      # OPENAI_API_KEY 만 채우면 된다 (LLM_PROVIDER 기본 openai, 네이버 키 불필요)

# 2) 실행
.venv\Scripts\python -m app.instant https://detail.1688.com/offer/XXXXXXXX.html
.venv\Scripts\python -m app.instant --fetch-only <URL>     # 페이지 수집만 확인 (키 불필요)
.venv\Scripts\python -m app.instant --headed --profile 1688 <URL>   # 창을 띄워 로그인 후 프로필 저장
.venv\Scripts\python -m app.instant --recent 10            # 이력
.venv\Scripts\python -m app.instant --show 20261030-091200 # 이력 1건 카드 다시 보기
```

- LLM 키가 없으면 추출 단계에서 멈춘다. 국내 가격 비교는 네이버 키가 필요 없다. 네이버 쇼핑 검색 API가 2026-07-31 종료되어 **네이버 통합검색의 쇼핑 블록을 크롤링**(`app/adapters/naver_crawl.py`)하며, 카드마다 최저가·배송비·리뷰 수·평점·찜·가격비교 판매처 수를 얻는다. 쇼핑 검색 페이지 본체(`search.shopping.naver.com`)는 헤드리스에서 로그인·차단 페이지로 튕겨서 쓰지 않는다.
- 환율은 수출입은행 API(키 있을 때) → 네이버 금융(2026-10 현재 페이지가 JS 앱으로 바뀌어 보통 실패) → open.er-api.com(키 없음, 실제로 쓰이는 경로) 순으로 자동 수집하고 `data/exchange_rates.json`에 48시간 캐시한다.
- 아직 미연결: 데이터랩 수요 신호, 동일 이미지 판매자 수, 리뷰 수 보조 크롤링, 텔레그램 입구. 카드에는 "미연결"로 표시된다.

코드 구조는 DESIGN.md 8장을 따른다: `app/sources/fetch.py`(페이지 스냅샷) → `app/pipeline/extract.py`(LLM 추출·정규화) → `app/pipeline/match.py`(네이버 매칭) → `app/pipeline/cost.py`(원가·점수) → `app/pipeline/card.py`. LLM 제공자는 `app/adapters/llm/` 에서 `LLM_PROVIDER`로 선택한다(OpenAI 기본·Claude 구현 완료, Gemini는 자리만). 모델은 `LLM_MODEL`로 바꾼다.
