## 1. 한 줄 컨셉

> 매일 새벽에 등록한 1688 카테고리들을 훑어 "국내에서 팔리고 있고, 경쟁이 적고, 충분히 싸게 들여올 수 있는 상품"을 찾아 아침 텔레그램으로 10건만 보여주고, 내가 승인한 것만 한국어 상세페이지까지 만들어 등록 직전 상태로 넘겨준다. 어느 PC에서 로그인해도 같은 데이터를 본다.

사람이 하는 일은 세 번의 클릭이다. 1차 승인(조사할 가치가 있는가), 2차 승인(이대로 올려도 되는가), 그리고 엑셀을 스마트스토어에 올리는 것.

## 2. 왜 이렇게 설계했나 (핵심 원칙)

- **상태는 전부 Supabase에, PC는 손과 눈만.** 로컬 DB가 없다. 크롤링·CLIP 추론·스케줄만 PC가 하고, 설정·후보·판단·이력은 계정에 묶여 클라우드에 있다. 집 맥과 회사 윈도우를 오가도 같은 화면이다.
- **공용과 개인을 가른다.** 사전·수집 상품·네이버 카드·매칭·환율처럼 "누가 봐도 같은 사실"은 공용 테이블에 쌓여 모든 계정이 재사용한다(같은 검색어는 두 번 크롤링하지 않는다). 내 배대지 요율·마진 기준·거절·주문처럼 "내 설정과 판단"은 개인 테이블에 RLS로 묶인다. 경계는 "내 배대지 요율을 바꾸면 값이 달라지는가"다.
- **AI는 최소로, 그리고 두 번 묻지 않는다.** 발굴 단계는 상품 1건당 LLM 0회다. 추출은 내장 어댑터, 정규화는 규칙 세트·별칭 사전, 매칭은 CLIP 이미지 유사도·이미지 해시·속성 규칙. LLM은 카드로 나갈 N건의 로고 확인, 규칙·사전에 없는 표기 제안, 승인된 상품의 한국어화에만 쓴다. 두 장치가 이를 보장한다: **AI 결과 캐시** — 모든 호출을 (용도·모델·입력 해시)로 공용 저장해 같은 입력이면 요청자가 달라도 재호출 없음(로고 확인은 이미지 해시가 키라 판매자가 사진을 바꾸기 전까지 1회). **규칙 세트** — AI는 소스×카테고리별 샘플을 1회 분석해 추출·정규화·검색어 규칙(선언적 DSL)을 만들고, 실행은 규칙 엔진이 한다. AI가 쓴 코드는 실행하지 않는다.
- **사이트 차이는 어댑터가 흡수한다.** 소스를 등록하고 어댑터 3종(내장 / 범용 CSS / LLM 추출) 중 하나로 붙인다. 발굴 MVP는 1688 내장 어댑터.
- **표기 차이는 사전이 흡수한다.** 과자 = 스넥 = 零食 = お菓子 = snack. 모르는 표기는 확인 큐에 쌓이고 admin이 확정하면 모든 계정에 적용된다.
- **비용은 전부 넣고, 값은 개인이 바꾼다.** 소스가, 현지 배송비, 대리구매 수수료, 배대지, 관부가세, 수수료, 환차손 완충까지 넣어 마진율을 계산한다.
- **사람이 거른다는 전제로 자동화한다.** CLIP 매칭은 LLM보다 오판이 많다. 재현율을 우선하고 정밀도는 1차 승인에서 사람이 맡는다. 카드에 이미지와 근거를 보여준다.
- **돈이 드는 단계는 승인 뒤로 미룬다.** 상세 수집과 콘텐츠 생성은 1차 승인된 상품만. 월 API 예산을 두고 80%에 경고, 100%에 중단.

## 3. 전체 흐름 (요약)

```
새벽(설정 시각)  ① 1688 카테고리 수집 → ② 사전 정규화 → ③ 네이버 조회(캐시·크롤링·CLIP 매칭) → ④ 개인 원가·점수      ← AI 0회/건
아침(설정 시각)  ⑤ 상위 N건 로고 비전 확인 → 텔레그램 1차 카드  [승인][거절][보류]
승인 즉시        ⑥ 상세 수집 → ⑦ 콘텐츠 생성(LLM) → ⑧ 텔레그램 2차 카드  [패키지 생성][수정 요청][폐기]
승인 즉시        ⑨ 이미지 Supabase 업로드 → 네이버 일괄등록 엑셀 행 생성
등록 후          ⑩ 설정 주기로 소스 재점검 → 텔레그램 [판매가 수정][판매 중지][무시]
```

## 4. 기능 목록

### 계정 · 데이터
- Supabase Auth 로그인(이메일). 역할 `admin`(공용 사전 관리) / `user`. PC마다 1회 로그인하면 세션 유지
- 공용 데이터: 소스 정의, 표준 카테고리(+한국어 검색 키워드), 별칭·속성 사전, 브랜드 블랙리스트, 스톱워드, 요건표, 네이버 카테고리, 수집 상품, 정규화 결과, 네이버 카드 캐시(TTL 7일), 이미지 해시·CLIP 임베딩(pgvector), 매칭, 시장 신호, 환율
- 개인 데이터: 설정(비용·매칭·건수·스케줄·예산·AI), 시크릿(Vault), 배송 프로필, 내 소스·관심 카테고리·제외 규칙, 후보와 판단, 거절 이력, 즉시 분석 이력, 콘텐츠·패키지·등록 상품·감시·주문, API 사용량, 실행 로그
- service_role 키는 PC에 두지 않음(마이그레이션·시드 전용). 워커·관리자 웹은 anon 키 + 로그인 JWT, RLS가 울타리

### 수집 · 정규화
- 소스 정의(공용)와 내 소스 설정(개인: 켜기, 요청 지연·하루 상한·차단 허용, 배송 프로필, PC별 로그인 프로필)
- 관심 카테고리(개인): 1688 카테고리 URL + 표준 카테고리 + 추가 한국어 키워드 + 페이지 수
- 1688 내장 어댑터(목록·상세, 셀렉터/내장 JSON, LLM 없음). 알리·범용 CSS·LLM 추출은 2차
- 규칙 세트(공용): 소스×카테고리별 추출·정규화·검색어 규칙을 AI가 샘플 1회 분석으로 생성(선언적 DSL: select·regex·unit·strip·map·template·default·flag), 샘플 커버리지 검증, admin 승인, 버전, 드리프트(커버리지 하락) 감지 → 재생성
- 정규화 런타임: 규칙 세트 → 사전 → 확인 큐 순. 스톱워드 제거, 숫자·단위 추출, 재질·품목 코드, 카테고리 상속·재확인, 브랜드 텍스트 블랙리스트, 공용 제외(식품·화장품·브랜드), 미등록 표기 확인 큐(LLM 제안은 하루 상한 안에서 묶어 1회, 같은 표기 재제안 없음)
- AI 결과 캐시(공용 `ai_results`): 모든 LLM 호출을 입력 해시로 저장. 로고 비전은 이미지 pHash, 미등록 사이트 추출은 URL+텍스트 해시, 상품명 초안은 source_item 키
- 사전 버전(`dict_version`): 사전이 바뀌면 다음 배치에서 비용 없이 재정규화

### 비교 · 원가
- 네이버 통합검색 쇼핑 블록 크롤링(API 종료) → 공용 캐시. 카드마다 최저가·배송비·리뷰·평점·찜·판매처 수·cat_id
- 매칭: CLIP 코사인 유사도 + 핵심 숫자 일치 규칙 → 정확/유사. pHash로 동일 이미지 판매자 수. 평균/중앙값/최저 모두 저장
- 수요 대리값: 리뷰·찜 구간 가점(데이터랩 붙으면 추이로 교체)
- 개인 원가: 공용 환율 × 내 배송 프로필·수수료율. 마진율, 제안 판매가, 후보 점수(마진 + 경쟁 + 수요 − 리스크)
- 하루 건수 세 가지: 수집 규모(카테고리별 페이지 수) / 분석 상한(네이버 조회·LLM 호출) / 카드 N(기본 10)

### 승인 · 생성 · 산출
- 상위 N건만 비전 LLM 로고 확인 → 텔레그램 1차 카드(이미지·원가·마진·경쟁·리뷰·근거)
- 2차 카드, 수정 요청 → 재생성, 보류 → 다음날 재알림
- 콘텐츠 생성 모드 A/B/C, 구매대행 고지 블록, 금지 문구 검사. 상품 실물 사진은 생성하지 않음
- Supabase Storage 공개 URL → 네이버 일괄등록 엑셀. 판매가 = 총원가 ÷ (1 − 목표 마진율), 100원 올림

### 등록 후 · 주문
- 등록 완료 표시 → 설정 주기(기본 3일) 소스 재점검, 가격 ±5%·품절·옵션·최소수량·삭제 감지 → 판매가 수정 / 판매 중지 / 무시
- 주문 처리 화면, 통관부호 체크리스트, 예상 도착일, 실제 원가, 월 손익 (2차)

### 시스템
- 배치 스케줄(개인), 같은 계정 PC 둘이면 DB 잠금으로 한 PC만 실행, 텔레그램 폴링도 임대를 가진 PC만
- API 월 예산(개인), 경고 비율, 초과 시 동작. 요약 메시지에 오늘 LLM 호출 수·비용 표시
- 관리자 웹(로컬 FastAPI, Supabase Auth 로그인) 메뉴 12개: 대시보드, 관심 카테고리, 후보 목록, 내 소스, 비용 설정, 매칭 설정, 제외 규칙, 사전 관리(admin), 소스 정의(admin), 시스템 설정, 실행 로그, 주문 관리

## 5. 기술 스택

Python 3.12 · **Supabase (Postgres + pgvector + Auth + Storage + Vault, supabase-py)** · Playwright · **CLIP (open_clip, 로컬 CPU) + imagehash** · FastAPI + Jinja2 + HTMX(로컬) · APScheduler · python-telegram-bot · OpenAI/Claude/Gemini 어댑터 · openpyxl

## 8-1. 지금 돌아가는 것: URL 즉시 분석 CLI (v2 경로, 2026-10-30)

v3의 "미등록 사이트 범용 경로"에 해당한다. 윈도우·맥별 설치와 테스트 순서는 [SETUP.md](SETUP.md). 상품 URL 하나를 넣으면 페이지를 읽고(Playwright), LLM이 정보를 뽑아 한국어로 정규화·요건·브랜드 판정을 하고, 네이버 통합검색 크롤링으로 비교가를 찾아 원가·마진율·후보 점수를 계산해 카드로 출력한다. 결과는 아직 로컬 `data/analyses/`에 남는다(v3 7단계에서 Supabase `analysis_requests`로 전환).

```bash
# 1) 준비 (최초 1회)
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
copy .env.example .env.dev  # OPENAI_API_KEY 만 채우면 된다 (LLM_PROVIDER 기본 openai, 네이버 키 불필요). 운영은 .env.prd + $env:APP_ENV="prd"

# 2) 실행
.venv\Scripts\python -m app.instant https://detail.1688.com/offer/XXXXXXXX.html
.venv\Scripts\python -m app.instant --fetch-only <URL>     # 페이지 수집만 확인 (키 불필요)
.venv\Scripts\python -m app.instant --headed --profile 1688 <URL>   # 창을 띄워 로그인 후 프로필 저장
.venv\Scripts\python -m app.instant --recent 10            # 이력
.venv\Scripts\python -m app.instant --show 20261030-091200 # 이력 1건 카드 다시 보기
```

- LLM 호출 3회/건(추출 · 정규화 · 매칭 판정, 합계 약 60~70원). v3 발굴 배치에서는 등록 소스라 이 셋이 0회가 된다.
- 국내 가격 비교는 네이버 키가 필요 없다. 네이버 쇼핑 검색 API가 2026-07-31 종료되어 **네이버 통합검색의 쇼핑 블록을 크롤링**(`app/adapters/naver_crawl.py`)하며, 카드마다 최저가·배송비·리뷰 수·평점·찜·가격비교 판매처 수를 얻는다. 쇼핑 검색 페이지 본체(`search.shopping.naver.com`)는 헤드리스에서 로그인·차단 페이지로 튕겨서 쓰지 않는다. 2026-11-01 윈도우에서 차단 없이 동작 확인.
- 환율은 수출입은행 API(키 있을 때) → 네이버 금융(JS 앱으로 바뀌어 보통 실패) → open.er-api.com(실제로 쓰이는 경로) 순으로 자동 수집하고 `data/exchange_rates.json`에 48시간 캐시한다.
- 아직 미연결: 데이터랩 수요 신호, 동일 이미지 판매자 수, 텔레그램 입구. 카드에는 "미연결"로 표시된다.

코드 구조: `app/sources/fetch.py`(페이지 스냅샷) → `app/pipeline/extract.py`(LLM 추출·정규화) → `app/pipeline/match.py`(네이버 매칭) → `app/pipeline/cost.py`(원가·점수) → `app/pipeline/card.py`. LLM 제공자는 `app/adapters/llm/` 에서 `LLM_PROVIDER`로 선택한다(OpenAI 기본·Claude 구현 완료, Gemini는 자리만). v3 구조(DESIGN.md 8장)에서 `cost.py`→`scoring.py`, `card.py`→`notify.py`로 승계되고 `extract.py`는 미등록 사이트 전용으로 남는다.
